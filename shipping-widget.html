The drop-in shipping button

One script tag and one element, on a page we do not own. This is that page — a pretend product listing, so the widget is seen where it will actually live rather than on a slide.

To see it work Start the backend, then serve this folder — npx serve . — and open localhost:3000/shipping-widget.html (or whichever port serve reports). Opening the file directly will render the button but cannot reach the API. You will need at least one live collection point at each end: sign shops up through the front door first.

What the merchant pasted

No build step, no framework, no configuration file.

<script src="https://sbg.example/embed/sbg-quote.js" defer></script>

<sbg-shipping-quote
  from-country="KE"
  from-area="Nairobi"
  length-cm="30" width-cm="20" height-cm="10" weight-kg="0.6"
></sbg-shipping-quote>

On this page the src points at the local build, 04_generated_sandbox/frontend/dist/embed/sbg-quote.js.

Attributes

AttributeWhat it does
from-pointThe collection point you ship from, by its public id. Exact.
from-country
from-area		…or where you ship from, and we find the point. One of these two forms is required — without either, the widget renders nothing and says why in the console.
length-cm
width-cm
height-cm		The packed box. All three or none: two of three is not a box, and half-measurements are dropped rather than sent.
weight-kgActual weight.
sizeS, M or L — the fallback when you have no measurements. Ignored when you do.
labelYour own words on the button.
localeBCP-47 tag for the money and date formats. Defaults to the visitor's.
keyYour publishable key (pk_…), so the rate limit is yours rather than shared with everyone behind your visitors' IP. Optional. A secret sk_ key here makes the widget refuse to render and tell your console to revoke it — by the time you read that, it is already in somebody's browser.
apiOverride the API root for one embed — staging, mostly.

Reading the answer

The widget shows the price. Your page gets the whole quote, so a checkout can add it to a total.

document.querySelector('sbg-shipping-quote')
  .addEventListener('sbg:quote', (e) => {
    console.log(e.detail.price.amount, e.detail.price.currency);
  });

With a key set, the quote also carries a quoteId. Keep it with the basket and hand it to the shipment call at checkout — then the buyer is charged the number they were just shown, not whatever the world has moved to by the time they pay.

How it behaves in somebody else's page

  • It cannot break your CSS and you cannot break it. The widget renders in a shadow root, so neither side's styles reach the other by accident.
  • It inherits your typography. A widget that shouts in its own house style looks bolted on, so it takes the page's font and colour. Three custom properties are the whole styling contract: --sbg-accent, --sbg-radius, --sbg-fg.
  • It brings no framework. Plain DOM, about 4 kB over the wire — a merchant should not pay for a UI runtime to render one price.
  • Configuration mistakes go to the console, never to the shopper. A misconfigured widget renders as though it were not on the page.
  • Failures are said in the buyer's terms. The server's message is written for a developer; the stable error code is what gets turned into a sentence about their situation.
  • The words are replaceable. Set window.SBG_QUOTE_STRINGS before the script loads to translate it, without a build.
