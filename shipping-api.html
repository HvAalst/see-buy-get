Quickstart

A price in one call. Nothing is created, so you can call it on every page view and on every change to the basket.

POST /v1/sbg/shipping/quotes
curl -X POST http://localhost:3000/v1/sbg/shipping/quotes \
  -H 'content-type: application/json' \
  -d '{
    "from": { "country": "KE", "area": "Nairobi" },
    "to":   { "country": "KE", "area": "Kisumu" },
    "dimensionsCm": { "l": 30, "w": 20, "h": 10 },
    "weightKg": 2
  }'
{
  "from": { "pointId": "did:glos:…", "name": "Nairobi CBD", "area": "Nairobi",
            "country": "KE", "landmark": "by the road", "openState": "open" },
  "to":   { "pointId": "did:glos:…", "name": "Kisumu Duka", "area": "Kisumu",
            "country": "KE", "openState": "open",
            "location": { "lat": -0.09, "lng": 34.77 } },
  "parcel": { "size": "M", "weightKg": 2 },
  "price":  { "currency": "KES", "amount": 32.13, "minimum": 32.13 },
  "eta":    { "readyAt": "2026-08-28T08:00:00.000Z", "hours": 13.6, "arrivesWhileOpen": false },
  "route":  { "hops": ["Nairobi CBD", "Kisumu Duka"], "km": 356.2,
              "crossesBorder": false, "crossings": [] },
  "requires": []
}
Show price.amount. It is the ceiling — the shipment will not cost more than this. price.minimum is what it costs if the seller commits to a single route. A buyer told 400 and charged 480 has been misled; one told 480 and charged 400 has not. In a sandbox with one carrier rate the two are equal.

Keys and modes

You do not need a key to quote, and you never will. A key buys you a rate limit of your own and the costed breakdown behind the number.

Issue them from your store console, under Store → Shipping API keys — as many as you like, one per environment or per storefront. Send one in a header; never in a query string, which ends up in access logs and referrers.

curl -X POST http://localhost:3000/v1/sbg/shipping/quotes \
  -H 'x-sbg-key: sk_live_…' \
  -H 'content-type: application/json' \
  -d '{ "from": {…}, "to": {…} }'

Two kinds

KindWhere it belongsWhat it does
pk_…In a page, in plain sight — the widget's key attribute.Asks what something costs. Nothing else. Readable back from your console whenever you rebuild a template, because it was never a secret.
sk_…On your server only.Everything a publishable key does, plus the breakdown. Shown once, at creation, and stored as a hash — so a breach of our table cannot be replayed as you.
Lost a secret key? There is exactly one honest answer: issue another and revoke the old one. We cannot show it to you again because we do not have it. Revoked keys are kept, not deleted, so “what was that key doing” stays a question you can answer.

Two modes

Every key is test or live, and says which in the key itself — a glance at a config file tells you which world it points at. Every response carries mode, so you are never in doubt about whether what you are looking at is real.

Today a test key quotes exactly as a live one does. That is not an omission — a quote creates nothing, so there is nothing for a sandbox to spare. The modes exist now because the credentials have to be separate before minting does: the point is that the key you develop with can never be the key that ships something.

The breakdown

With a secret key, the response gains a breakdown: every stop's own published fee and the currency it is owed in, the transport, the margin rate, and the exchange rates if any were applied. Each participant advertises its own rate and competition depends on that being visible — what it is not is something to hand a stranger with a scraper.

"breakdown": {
  "nodes": [
    { "type": "pudo", "label": "Nairobi CBD", "country": "KE",
      "fee": 1.5, "nativeFee": 1.5, "currency": "KES" },
    { "type": "pudo", "label": "Kisumu Duka", "country": "KE",
      "fee": 1.5, "nativeFee": 1.5, "currency": "KES" }
  ],
  "nodeFees": 3,
  "transport": 28.5,
  "platformFeePct": 0.02
}

The key is absent rather than empty when you have not earned it — there is nothing to probe at.

Naming a place

Both ends of a quote take the same shape, and you can use either form on either end.

By collection point

Exact, and what your checkout already holds if you use the PUDO picker. Point ids are public — they come from the network directory at GET /v1/sbg/network/points.

{ "pointId": "did:glos:7f3a…" }

By country and area

What a person actually knows. We pick the collection point with the most room, and the same ask gives the same answer twice. Choosing one reserves nothing — it is where they would collect.

{ "country": "KE", "area": "Kisumu" }
Only live shops are offered. A point that has not finished signing up is never returned and is refused if you name it. A quote should describe somewhere a person can actually stand.

Quote reference

Request

FieldTypeDescription
from requiredobjectWhere the shipment is collected. pointId, or country + area.
to requiredobjectWhere the buyer collects it. Same shape.
dimensionsCmobjectl, w, h in centimetres. Give these when you have them.

Creating a shipment

The half that is not safe to repeat. Needs a secret key, and you should send an idempotency key with it.

POST /v1/sbg/shipping/shipments
curl -X POST http://localhost:3000/v1/sbg/shipping/shipments \
  -H 'x-sbg-key: sk_test_…' \
  -H 'idempotency-key: 0f8c2b1e-order-4471' \
  -H 'content-type: application/json' \
  -d '{
    "from": { "country": "KE", "area": "Nairobi" },
    "to":   { "country": "KE", "area": "Kisumu" },
    "dimensionsCm": { "l": 30, "w": 20, "h": 10 },
    "weightKg": 2,
    "buyerMobile": "+254700123456",
    "contentPhotoRef": "med_9f21…",
    "externalOrderId": "SO-4471"
  }'
{
  "shipmentId": "PUD-9C4A1B7E2F",
  "did": "did:glos:…",
  "trackingKey": "T-4B1C9E7A02",
  "externalOrderId": "SO-4471",
  "status": "Created",
  "paid": true,
  "price": { "currency": "KES", "amount": 32.13 },
  "parcel": { "size": "M", "weightKg": 2 },
  "collect": { "pointId": "did:glos:…", "name": "Kisumu Duka", "area": "Kisumu", … },
  "eta": { "readyAt": "2026-08-28T08:00:00.000Z" },
  "route": { "crossesBorder": false, "crossings": [] },
  "label": { … },
  "mode": "live",
  "simulated": false,
  "replayed": false
}

The store is the key

There is no store field in that request. The shipment is minted against whoever the secret key belongs to, so a merchant cannot mint on somebody else's account by changing a value — there is nothing to change. A publishable key is refused here: a credential that ships things must never sit in a page.

FieldTypeDescription
from · toobjectExactly as on a quote.
dimensionsCm · weightKg · size—Exactly as on a quote; the tier is derived the same way.
buyerMobile requiredstringSomebody has to be told where to collect it.
contentPhotoRef requiredstringA photo of the contents, uploaded first. It is the baseline a damage claim is judged against — which is why we do not make it optional for an API caller when it is required of everyone else.
externalOrderIdstringYour own reference. Carried through and returned on every status callback.
items · subtotal—What is in the box and what it is worth. Required when the route crosses a border — see crossing a border.
routeModeflexible · lockedReserve the ceiling and get the difference back on delivery, or commit to the cheapest route now. Defaults to flexible.
The collection code is not in that response, and will not be. It is the handover secret — the only thing between a stranger and the parcel — and it belongs to the person collecting, in their own app. Track the shipment with trackingKey.

Not paid yet

paid: false is not an error. The shipment exists and is waiting on your prepaid balance; a label is a claim on the network, so it does not issue until the shipment is paid for. Top up and it settles.

Retrying safely

Send an Idempotency-Key header — any string you can reproduce, your own order id is ideal. Then:

  • The same key with the same request returns the first answer with replayed: true. Nothing is created twice.
  • The same key with a different request is refused with IDEMPOTENCY_REUSED. It means two shipments are sharing one name — quietly returning the first would ship the wrong parcel and report success.
  • A key still in flight is refused with CONFLICT. Wait, then retry.
  • A failed attempt releases its key, so you can fix the problem — a top-up that had not landed — and retry with the same one.
  • Keys are remembered for 24 hours and scoped to your account.

Test mode

A test key runs every check a live one runs — the same resolution, the same derived size, the same cargo gate, the same customs declaration, the same price — and then commits nothing. No parcel, no billing, no label, and nobody told to collect anything.

What it cannot do is give you something to track. simulated: true, a test_… id, and no did — because a shipment that does not exist has nothing to follow, and pretending otherwise is the one thing a sandbox must not do. Everything else is real: a request refused in test is refused live for the same reason, and one that works in test would have worked.

Where we deliver

Every country the network operates in and the areas inside it that have a collection point. This is what a destination picker is built from.

GET /v1/sbg/shipping/areas
[
  { "country": "ET", "areas": ["AddisAbaba"] },
  { "country": "KE", "areas": ["Kisumu", "Nairobi"] }
]

An area appears only when somebody there is live and taking parcels, so anything in this list is something a quote will answer. For the company behind each country and the money it settles in, see GET /v1/sbg/countries.

The drop-in button

If you do not want to call the API yourself, paste this instead. One script tag and one element, no build step and no framework.

<script src="https://sbg.example/embed/sbg-quote.js" defer></script>

<sbg-shipping-quote
  from-country="KE"
  from-area="Nairobi"
  length-cm="30" width-cm="20" height-cm="10" weight-kg="0.6"
></sbg-shipping-quote>

The button opens a destination picker, calls /shipping/quotes, and shows the price, where the buyer would collect it and when. Your page gets the whole quote:

document.querySelector('sbg-shipping-quote')
  .addEventListener('sbg:quote', (e) => {
    console.log(e.detail.price.amount, e.detail.price.currency);
  });
AttributeWhat it does
from-pointThe collection point you ship from, by its public id.
from-country · from-area…or where you ship from, and we find the point. one form required
length-cm · width-cm · height-cmThe packed box. All three or none — two of three is not a box, and half-measurements are dropped rather than sent.
weight-kgActual weight.
sizeS · M · L, when you have no measurements. Ignored when you do.
labelYour own words on the button.
localeBCP-47 tag for money and date formats. Defaults to the visitor's.
keyYour publishable key, so the rate limit is yours. A sk_ key here makes the widget refuse to render and tell your console to revoke it — by then it is already public.
apiOverride the API root for one embed.
It renders in a shadow root. Your CSS cannot reach into it and its CSS cannot reach out. It takes your font and colour so it does not look bolted on; --sbg-accent, --sbg-radius and --sbg-fg are the whole styling contract. Roughly 4 kB over the wire, and no framework — you should not pay for a UI runtime to render one price.

Set window.SBG_QUOTE_STRINGS before the script loads to replace any of its words. A misconfigured widget logs to the console and renders nothing — a shopper should never be shown a setup error. There is a working demo at shipping-widget.html.

Crossing a border

A continental quote is a real one: it plans across the border, names the leg that crosses, and converts the far shop's price into the money you are billed in.

  • One currency, named. price.currency is the selling company's. Shops in another country are paid in their own money; the conversion happens in the quote.
  • The price has a shelf life. When a rate was applied, expiresAt is set. Re-quote after it, rather than honouring a stale figure.
  • The rate carries a buffer against the market moving between quote and settlement, and the buyer carries it. We do not profit from exchange rates: what the buffer absorbs is booked as an FX difference, not as margin.
  • A crossing needs paperwork. requires contains customs_declaration. When you mint the shipment you must send a contents list and a declared value, or it is refused. Duties are the importer's — DDU — and none of it moves through us.
  • A border post costs time, and it is in the ETA rather than hidden in the driving.
Two currencies with no rate between them cannot be priced. You get FX_REQUIRED rather than a plausible wrong number. Adding one currency to another is not arithmetic, and a quote that pretends otherwise is worse than one that refuses.

Errors

Every failure is an RFC 9457 problem document with a stable machine-readable code. Show the code's meaning to a person; log the detail.

CodeStatusWhat happened
FIELD_REQUIRED400An end of the journey was not named — no point id and no area.
VALIDATION_FAILED400A field was the wrong shape. The body names which.
INVALID_INPUT400Both ends resolved to the same point, or a country was not a two-letter code.
NOT_FOUND404No such collection point, it is not taking parcels yet, or no point exists in that area.
NO_CAPACITY_AVAILABLE400Every collection point in that area is full right now. Try another area.

FX_REQUIRED400The route spans two currencies with no exchange rate between them.

  "type": "https://glos.dev/problems/NO_CAPACITY_AVAILABLE",
  "title": "No pick-up point with free capacity",
  "status": 400,
  "code": "NO_CAPACITY_AVAILABLE",
  "detail": "Every collection point in Kisumu is full right now",
  "message": "Every collection point in Kisumu is full right now",
  "retryable": false,
  "traceId": "trc_9f1c…",
  "instance": "/v1/sbg/shipping/quotes"
}

message is an alias of detail for older clients. retryable says whether the same request may be sent again unchanged. traceId correlates the response with our logs — quote it if you report a problem. Some codes add a params object: a validation failure lists violations, a rate limit carries retryAfterSec.

Limits

  • 60 quotes a minute per caller, 30 shipments, and 120 for /areas. Generous for a product page, useless for a scrape. Exceeding it is a 429 with retryAfterSec.
  • Counted per KEY when you send one, and per IP when you do not — which is the practical reason to use one: without a key your limit is shared with everyone behind the same address.
  • A quote creates nothing and reserves nothing — asking it twice costs nothing and changes nothing, so it is always safe to retry. A shipment is the opposite, which is what Idempotency-Key is for.

Not here yet

Said plainly, because you will ask. None of these exist today and none of them are faked.

  • A quote you can redeem. The price is not held against a reference: minting re-prices at the moment you commit. expiresAt tells you when a converted price is worth re-asking for.
  • Cancelling or amending through this API. A shipment is created here and then lives in the merchant console.
  • A media upload on this surface. contentPhotoRef comes from the authenticated media endpoint.
  • Free-text destinations. You name a point or an area, not “12 Biashara Street”. Place look-up covers Kenya only today.
  • Translations for the button. Its words are English until you replace them with window.SBG_QUOTE_STRINGS; it is not wired to the network's own translation catalogues.
  • Minting from the button. It quotes. Turning a quote into a shipment is still the authenticated merchant API.
