Quickstart

A price in one call. Nothing is created, so you can call it on every page view and on every change to the basket.

POST /v1/sbg/shipping/quotes
curl -X POST http://localhost:3000/v1/sbg/shipping/quotes \
  -H 'content-type: application/json' \
  -d '{
    "from": { "country": "KE", "area": "Nairobi" },
    "to":   { "country": "KE", "area": "Kisumu" },
    "dimensionsCm": { "l": 30, "w": 20, "h": 10 },
    "weightKg": 2
  }'
{
  "from": { "pointId": "did:glos:…", "name": "Nairobi CBD", "area": "Nairobi",
            "country": "KE", "landmark": "by the road", "openState": "open" },
  "to":   { "pointId": "did:glos:…", "name": "Kisumu Duka", "area": "Kisumu",
            "country": "KE", "openState": "open",
            "location": { "lat": -0.09, "lng": 34.77 } },
  "parcel": { "size": "M", "weightKg": 2,
              "chargedBy": { "by": "weight", "countsAsKg": 2, "weighsKg": 2 } },
  "price":  { "currency": "KES", "amount": 32.13, "minimum": 32.13 },
  "eta":    { "readyAt": "2026-08-28T08:00:00.000Z", "hours": 13.6, "arrivesWhileOpen": false },
  "route":  { "hops": ["Nairobi CBD", "Kisumu Duka"], "km": 356.2,
              "crossesBorder": false, "crossings": [] },
  "requires": []
}
Show price.amount. It is the ceiling — the shipment will not cost more than this. price.minimum is what it costs if the seller commits to a single route. A buyer told 400 and charged 480 has been misled; one told 480 and charged 400 has not. In a sandbox with one carrier rate the two are equal. Send a key and the answer also carries a quoteId: hand that back when you create the shipment and it is minted at this price, not at whatever the world has moved to by then.

Keys and modes

You do not need a key to quote, and you never will. A key buys you a rate limit of your own and the costed breakdown behind the number.

Issue them from your store console, under Store → Shipping API keys — as many as you like, one per environment or per storefront. Send one in a header; never in a query string, which ends up in access logs and referrers.

curl -X POST http://localhost:3000/v1/sbg/shipping/quotes \
  -H 'x-sbg-key: sk_live_…' \
  -H 'content-type: application/json' \
  -d '{ "from": {…}, "to": {…} }'

Two kinds

KindWhere it belongsWhat it does
pk_…In a page, in plain sight — the widget's key attribute.Asks what something costs. Nothing else. Readable back from your console whenever you rebuild a template, because it was never a secret.
sk_…On your server only.Everything a publishable key does, plus the breakdown. Shown once, at creation, and stored as a hash — so a breach of our table cannot be replayed as you.
Lost a secret key? There is exactly one honest answer: issue another and revoke the old one. We cannot show it to you again because we do not have it. Revoked keys are kept, not deleted, so “what was that key doing” stays a question you can answer.

Two modes

Every key is test or live, and says which in the key itself — a glance at a config file tells you which world it points at. Every response carries mode, so you are never in doubt about whether what you are looking at is real.

Today a test key quotes exactly as a live one does. That is not an omission — a quote creates nothing, so there is nothing for a sandbox to spare. The modes exist now because the credentials have to be separate before minting does: the point is that the key you develop with can never be the key that ships something.

The breakdown

With a secret key, the response gains a breakdown: every stop's own published fee and the currency it is owed in, the transport, the margin rate, and the exchange rates if any were applied. Each participant advertises its own rate and competition depends on that being visible — what it is not is something to hand a stranger with a scraper.

"breakdown": {
  "nodes": [
    { "type": "pudo", "label": "Nairobi CBD", "country": "KE",
      "fee": 1.5, "nativeFee": 1.5, "currency": "KES" },
    { "type": "pudo", "label": "Kisumu Duka", "country": "KE",
      "fee": 1.5, "nativeFee": 1.5, "currency": "KES" }
  ],
  "nodeFees": 3,
  "transport": 28.5,
  "platformFeePct": 0.02
}

The key is absent rather than empty when you have not earned it — there is nothing to probe at.

Naming a place

Both ends of a quote take the same shape, and you can use either form on either end.

By collection point

Exact, and what your checkout already holds if you use the PUDO picker. Point ids are public — they come from the network directory at GET /v1/sbg/network/points.

{ "pointId": "did:glos:7f3a…" }

By address, in the buyer's own words

What a person actually has. We place it and return the nearest collection point, with how far it is and what we understood them to mean — so they can see we read them right.

{ "country": "ET", "address": "Bole, Addis Ababa" }

→ "to": { "name": "Bambi's Super Market", "matchedPlace": "Bole", "distanceKm": 2.4, … }

country is optional and narrows the search. Text we cannot place gets one more chance as the name of an area we serve, so “Kisumu” and “12 Oginga Odinga St, Kisumu” both work from one input.

An address we cannot place is refused, not guessed at. You get NOT_FOUND with “we could not place …”. Sending somebody to a collection point chosen by a hash of their own typo would be worse than telling them we did not understand. Coverage is a real gazetteer for Kenya and Ethiopia — town and neighbourhood level, not street level.

By country and area

An area we already serve, named exactly. We pick the collection point with the most room, and the same ask gives the same answer twice. Choosing one reserves nothing — it is where they would collect.

{ "country": "KE", "area": "Kisumu" }
Only live shops are offered. A point that has not finished signing up is never returned and is refused if you name it. A quote should describe somewhere a person can actually stand.

Quote reference

Request

FieldTypeDescription
from requiredobjectWhere the shipment is collected. pointId, or country + area.
to requiredobjectWhere the buyer collects it. Same shape.
dimensionsCmobjectl, w, h in centimetres. Give these when you have them.

The tier is derived, not chosen. Send measurements and the size comes from them — the same rule every shipment in the network is minted under, so a quote and the shipment it becomes cannot disagree about how big the parcel was.
Size or weight, whichever is more. A measured parcel counts by its size as l × w × h ÷ 7875 kilograms — a box of 45 × 35 × 25 cm counts as 5 kg, the room our medium size allows for its weight — and is priced on whichever is more: what it weighs, or what it counts as. A box of 50 × 40 × 30 cm weighing 6 kg is priced as 7.6 kg. The answer says which one set the price in parcel.chargedBy, so you can tell your buyer why a big, light box costs more. Many carriers divide by 5,000 or 6,000; we divide by 7,875, so a box counts as lighter here. Send real measurements: without them a parcel is priced at its whole size tier.

Creating a shipment

The half that is not safe to repeat. Needs a secret key, and you should send an idempotency key with it.

First, the photo of what is in the box

Every shipment names a photo of its contents: it is the “before” a damage claim is judged against. Send it first, with the same secret key, and name the photoId you get back as contentPhotoRef.

POST /v1/sbg/shipping/photos
curl -X POST http://localhost:3000/v1/sbg/shipping/photos \
  -H 'x-sbg-key: sk_test_…' \
  -H 'content-type: application/json' \
  -d '{ "dataUrl": "data:image/jpeg;base64,/9j/4AAQ…" }'
{
  "photoId": "med_9f21…",
  "keptUnusedUntil": "2026-10-22T09:14:03.000Z"
}
  • The image as a data URL: JPEG, PNG or WebP, up to 500 KB. Make it smaller before you send it — a phone photo resized to about 1600 pixels on its long side is plenty. thumbDataUrl, up to 64 KB, is optional: a small copy shown in lists before the full photo is asked for.
  • One photo, one shipment. The shipment that names it keeps it as its evidence, for as long as the shipment's records are kept. Naming it again for another shipment is refused: each box is photographed for itself.
  • Unused, it goes. A photo no shipment names is removed at keptUnusedUntil, two days after it was sent.
  • A test key sends photos too, so you can try the whole path. A test shipment checks the photo and keeps nothing, so the same photo can still be named by a live one.

Then the shipment

POST /v1/sbg/shipping/shipments
curl -X POST http://localhost:3000/v1/sbg/shipping/shipments \
  -H 'x-sbg-key: sk_test_…' \
  -H 'idempotency-key: 0f8c2b1e-order-4471' \
  -H 'content-type: application/json' \
  -d '{
    "from": { "country": "KE", "area": "Nairobi" },
    "to":   { "country": "KE", "area": "Kisumu" },
    "dimensionsCm": { "l": 30, "w": 20, "h": 10 },
    "weightKg": 2,
    "buyerMobile": "+254700123456",
    "contentPhotoRef": "med_9f21…",
    "externalOrderId": "SO-4471"
  }'
{
  "shipmentId": "PUD-9C4A1B7E2F",
  "did": "did:glos:…",
  "trackingKey": "T-4B1C9E7A02",
  "externalOrderId": "SO-4471",
  "status": "Created",
  "paid": true,
  "price": { "currency": "KES", "amount": 32.13 },
  "parcel": { "size": "M", "weightKg": 2 },
  "collect": { "pointId": "did:glos:…", "name": "Kisumu Duka", "area": "Kisumu", … },
  "eta": { "readyAt": "2026-08-28T08:00:00.000Z" },
  "route": { "crossesBorder": false, "crossings": [] },
  "label": { … },
  "sscc": "261612340000000001",
  "mode": "live",
  "simulated": false,
  "replayed": false
}

sscc is there when your store has given its GS1 company prefix in the Store app (My store, then “GS1 barcodes on your parcels”) and the shipment is paid for: its own Serial Shipping Container Code, under your prefix, printed on the label as a GS1-128 barcode beside our QR. It is the shipment’s for good: it does not change if you change your prefix, and no other shipment is ever given it. Without a prefix, or before it is paid, the field is not sent.

Redeeming a held price

Between a product page and a checkout, everything a price rests on is free to move — a shop's own advertised rate, a margin, a carrier range, an exchange rate. Send the quoteId from the quote and the shipment is minted at the figure your buyer was shown, instead of at today's.

{
  "quoteId": "qt_7b31c0a4f9…",
  "buyerMobile": "+254700123456",
  "contentPhotoRef": "med_9f21…",
  "externalOrderId": "SO-4471"
}

A held quote already says where the shipment goes and how big it is, so from, to, dimensionsCm, weightKg and size must not be sent with it. A request carrying both is refused rather than resolved in one direction: a quote that says “M to Kisumu” and a body that says “L to Nakuru” is a caller who believes two different things about one shipment.

  • Held for an hour, or until the exchange rate behind it expires, whichever comes first — a converted price cannot outlive the rate it was converted at.
  • One quote, one shipment. Redeeming twice is QUOTE_SPENT. To retry a request you are unsure about, use Idempotency-Key, which is what it is for.
  • A failed mint leaves the price held, so you can fix what was wrong and redeem the same promise rather than go back to your buyer with a different number.
  • We hold the price, not the world. A held quote survives the route getting dearer. It does not survive a collection point that has stopped taking parcels — that is NOT_FOUND and a reason to re-quote, because a price promise should not become an undeliverable parcel.
  • A test quote and a live key do not mix, in either direction.
  • A quote asked for without a key has no quoteId: we cannot promise a price to somebody we will not recognise when they come back to claim it.

The store is the key

There is no store field in that request. The shipment is minted against whoever the secret key belongs to, so a merchant cannot mint on somebody else's account by changing a value — there is nothing to change. A publishable key is refused here: a credential that ships things must never sit in a page.

FieldTypeDescription
quoteIdstringA price held earlier. Give this or the four fields below — never both.
from · toobjectExactly as on a quote. Required when there is no quoteId.
dimensionsCm · weightKg · size—Exactly as on a quote; the tier is derived the same way.
buyerMobile requiredstringSomebody has to be told where to collect it.
contentPhotoRef requiredstringThe photoId from POST /v1/sbg/shipping/photos: a photo of this shipment’s contents, used for no other. It is the baseline a damage claim is judged against — which is why we do not make it optional for an API caller when it is required of everyone else. A name, or an id we do not hold, is refused with PHOTO_REQUIRED — by a test key exactly as by a live one.
externalOrderIdstringYour own reference. Carried through and returned on every status callback.
items · subtotal—What is in the box and what it is worth. Required when the route crosses a border — see crossing a border.
routeModeflexible · lockedReserve the ceiling and get the difference back on delivery, or commit to the cheapest route now. Defaults to flexible.
The collection code is not in that response, and will not be. It is the handover secret — the only thing between a stranger and the parcel — and it belongs to the person collecting, in their own app. Track the shipment with trackingKey.

Not paid yet

paid: false is not an error. The shipment exists and is waiting on your prepaid balance; a label is a claim on the network, so it does not issue until the shipment is paid for. Top up and it settles.

Retrying safely

Send an Idempotency-Key header — any string you can reproduce, your own order id is ideal. Then:

  • The same key with the same request returns the first answer with replayed: true. Nothing is created twice.
  • The same key with a different request is refused with IDEMPOTENCY_REUSED. It means two shipments are sharing one name — quietly returning the first would ship the wrong parcel and report success.
  • A key still in flight is refused with CONFLICT. Wait, then retry.
  • A failed attempt releases its key, so you can fix the problem — a top-up that had not landed — and retry with the same one.
  • Keys are remembered for 24 hours and scoped to your account.

Test mode

A test key runs every check a live one runs — the same resolution, the same derived size, the same cargo gate, the same customs declaration, the same price — and then commits nothing. No parcel, no billing, no label, and nobody told to collect anything.

What it cannot do is give you something to track. simulated: true, a test_… id, and no did — because a shipment that does not exist has nothing to follow, and pretending otherwise is the one thing a sandbox must not do. Everything else is real: a request refused in test is refused live for the same reason, and one that works in test would have worked.

Reading and cancelling

A shipment you created here can be read and called off here. You do not have to log in to find out where it got to.

Where is it?

curl https://api.seebuyget.example/v1/sbg/shipping/shipments/PUD-A1B2C3D4E5 \
  -H "X-SBG-Key: sk_live_…"
{
  "shipmentId": "PUD-A1B2C3D4E5",
  "trackingKey": "T-9F8E7D6C5B",
  "externalOrderId": "SO-1183",
  "status": "At_PUDO",
  "paid": true,
  "price": { "currency": "KES", "amount": 240.00 },
  "cancellable": true,
  "createdAt": "2026-09-06T08:12:04.000Z",
  "sscc": "261612340000000018"
}

The price is the one it was SOLD at, read off the shipment itself — not a fresh quote. Ask this a year later and it still answers what you were charged, which is what makes it safe to reconcile an invoice against.

The collection code is not here. You are told it on the ready_for_pickup callback, at the moment it is useful and to an endpoint you registered. On an endpoint you can poll it would end up in every log file that ever recorded a response body.

A shipment belonging to another store answers 404, not 403. "You may not see this" would confirm the id is real to somebody working through a list of them.

Its label, again — or for a thermal printer

curl https://api.seebuyget.example/v1/sbg/shipping/shipments/PUD-A1B2C3D4E5/label?format=zpl \
  -H "X-SBG-Key: sk_live_…"

The label the shipment issued once it was paid, asked for again. Without format, or with format=svg, it comes as it did when you created the shipment: { parcelId, qrPayload, svg }. With format=zpl it comes as ZPL, text/plain, for a thermal label printer at 203 dpi with 100 × 150 mm labels — send it to the printer as it is. Ask on each request, so a system printing on two kinds of printer asks for each.

Needs a secret key, as creating the shipment did: a label is a claim on the network. Not paid yet, you get INVALID_STATE; a shipment of another store, 404; a test key made nothing, so there is no label to print. A label never carries the collection code — only the shipment id in its QR and the trackingKey.

Calling it off

curl -X POST https://api.seebuyget.example/v1/sbg/shipping/shipments/PUD-A1B2C3D4E5/cancel \
  -H "X-SBG-Key: sk_live_…" \
  -H "content-type: application/json" \
  -d '{ "reason": "buyer changed their mind" }'

Needs a secret key, for the reason creating one does: a credential that can undo a shipment must never sit in a page. reason is optional and kept on the audit trail.

You can cancel while the shipment is Created, At_PUDO or At_MDP — that is, until somebody is actually carrying it. cancellable on the read above tells you before you try. Past that point it is a conversation rather than an API call, and you get INVALID_STATE, with why in detail.

What it does to your money depends on where it is.

  • Not yet handed in, or still at the shop it was handed in at (Created, At_PUDO): it is withdrawn (Voided) and its price comes back to your balance in full.
  • At a hub (At_MDP): it is not withdrawn — the goods would sit at the hub belonging to no journey. It is turned round there and brought back to the shop it was handed in at, as a new shipment you pay for; what it cost to get it to the hub is not given back. The hub prints its new label and puts it over the old one. The answer comes back Returned, with returnShipmentId: the new shipment, yours to read like any other (it says returnOf, the one it brings back), collected at that shop with its own collection code. Your balance must cover it, or you get WALLET_INSUFFICIENT and nothing changes. It cannot be brought back where that shop is not taking parcels: then it carries on to your buyer, and you get INVALID_STATE saying so. Or, with backTo: "door", it comes to your own door as a load instead, as below, where your store has a door on the map. No other shop is chosen for it: any other backTo gets INVALID_STATE.
  • At a hub, and never handed in at a shop — collected at your own door, or handed in at a hub: you say where it comes back to, with backTo in the body. Either a collection point's id (pointId from the directory): it comes back there as above, a new shipment you pay for. Or "door": your own door — your collection point, or your store's pin — as a load posted from the hub, with maxSpend, the most you pay a driver. The first driver whose vehicle fits takes it, at their own price and never above what you allow; you are billed when a driver takes it. The answer says returnLoad, the load's code. The load cannot be withdrawn (the goods would wait at the hub for nobody); the hub hands the box only to the driver who took it. While no driver has taken it, you can raise the most you pay, or send the box to a shop instead: a new shipment you pay for, the load withdrawn, nothing of it billed. Both are in your store's app, under Sent as freight. If no driver has taken it after a day, you are told there. Without backTo you get FIELD_REQUIRED and nothing changes.
curl -X POST https://api.seebuyget.example/v1/sbg/shipping/shipments/PUD-A1B2C3D4E5/cancel \
  -H "X-SBG-Key: sk_live_…" \
  -H "content-type: application/json" \
  -d '{ "reason": "buyer cancelled", "backTo": "door", "maxSpend": 5 }'

What would calling it off do? Ask first

curl https://api.seebuyget.example/v1/sbg/shipping/shipments/PUD-A1B2C3D4E5/call-off \
  -H "X-SBG-Key: sk_live_…"
{
  "parcelId": "PUD-A1B2C3D4E5",
  "outcome": "bring_back",
  "amount": 180.00,
  "currency": "KES",
  "backTo": "Nairobi CBD",
  "atHub": "Naivasha Hub"
}

Changes nothing. outcome is refund (with the amount that would come back), bring_back (with what bringing it back would cost, the shop it would come back to and the hub it is at), pick (never handed in at a shop: ask again with ?backTo= a collection point's id, or door — door is said when you have one on the map), to_door (with suggestedMax, the most we suggest allowing a driver — a suggestion: each driver's price decides), or no (with why). The price of bringing it back is today's: asked again later, it may differ.

There is no amend, on purpose

Moving a shipment's destination or changing its size changes what it costs. An "edit" that quietly re-prices something your buyer has already paid for is the worst possible version of this call, so it does not exist: cancel it and create the replacement, and the new price is one somebody can see and agree to.

Test keys

A test mint creates nothing, so there is nothing to read or cancel. Both calls say exactly that rather than answering a bare 404 that reads like a bug in your own integration.

Status callbacks

You do not have to poll. Register a callback URL and the network tells you when a shipment moves.

The URL and the signing secret are set on your store record, not on a key — they belong to the merchant, not to a credential you might rotate.

What you get

POST https://your-shop.example/hooks/sbg
content-type: application/json

{
  "event": "ready_for_pickup",
  "data": {
    "parcelId": "PUD-A1B2C3D4E5",
    "externalOrderId": "SO-1183",
    "status": "Ready_For_Pickup",
    "collectionCode": "8412",
    "binSlot": "B-04"
  },
  "at": "2026-09-06T14:02:11.000Z"
}

The events

  • parcel_paid — your prepaid balance covered it and the label is unblocked.
  • ready_for_pickup — it is on the shelf and the buyer can collect. This is the one that carries the collection code, which is what you tell your buyer — unless you have switched that off on your store record (Store app → My store → Callbacks): buyers who sign in to the Send app with the phone number they gave you read the code there, get told when the parcel arrives, and can message the shop, and once yours do the code need never leave the network. A reissued code sends this event again with the new one: same status, new code, which is exactly what somebody standing at a counter unable to collect needs.
  • collected — the buyer has it. The order is closed.
  • disputed — something is wrong with it; data.disputeReason says what was claimed.
  • held — a shop or a hub found its wrap or packaging cut or opened, photographed it and set it apart. data.held says what was found (finding), where (where) and since when (since). It goes into no bag and to nobody until SeeBuyGet operations has looked and released it; your buyer cannot collect it meanwhile.
  • released — operations released it: it goes on as usual. What was found stays on its record.

A shipment brought back from a hub after you called it off is one you never created yourself: its callbacks carry data.returnOf, the shipment it brings back, so your system can tie the two together. Its ready_for_pickup carries the code you collect it with, at the shop it comes back to. One coming to your door as a load is heard by the load.* events, which carry data.bringsBack: the shipment it brings back.

Checking it really came from us

Every callback is signed: HMAC-SHA256 over the exact request body, keyed with your store secret, hex-encoded, in the x-sbg-signature header. Verify against the raw bytes you received — re-serialising the JSON first will change the whitespace and the signature will not match.

Two other headers ride along. x-sbg-event repeats the event name, so you can route before parsing. x-sbg-delivery is the id of this delivery and stays the same across retries — it is the key to be idempotent on.

const expected = crypto.createHmac('sha256', STORE_SECRET).update(rawBody).digest('hex');
if (!crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(received))) return res.sendStatus(401);

Compare in constant time, as above. A plain === on a signature leaks how much of it was right, one character at a time.

Delivery, retries and giving up

Callbacks are posted to your URL. This page said for a long time that they were recorded and not delivered, which was true and is no longer: they are sent now, and the outbox in the merchant console shows whether each one actually arrived rather than only that it was created.

  • Answer 2xx and we are done. Anything else, or no answer within thirty seconds, is a failure.
  • We retry with a backoff — five minutes, then fifteen, an hour, three, six, twelve and twenty-four — eight attempts over about two days, after which we stop and mark it failed in your outbox with the reason.
  • A retry carries the identical body, signature and x-sbg-delivery. That is deliberate: a late delivery has to verify exactly as the first one would have.
  • So be idempotent, on x-sbg-delivery or on parcelId + event. You can be sent the same event twice.
  • In the Store app, under My store, every message says whether it arrived, is still being tried (and when next, and why not), or was given up. Send again sends that same message — same x-sbg-delivery, same body — to the address you have now, signed with the secret you have now, with a fresh round of tries. Send a test message sends one with event: "test", to check your endpoint takes and verifies ours.

Answer fast and do your work afterwards. We are not waiting on your order pipeline, and an endpoint that takes thirty seconds to reply is an endpoint we will treat as down.

Your URL has to be https and must resolve to a public address — we will not post to anything inside a private network, and we never pass your endpoint's response body back to anyone.

Where we deliver

Every country the network operates in and the areas inside it that have a collection point. This is what a destination picker is built from.

GET /v1/sbg/shipping/areas
[
  { "country": "ET", "areas": ["AddisAbaba"] },
  { "country": "KE", "areas": ["Kisumu", "Nairobi"] }
]

An area appears only when somebody there is live and taking parcels, so anything in this list is something a quote will answer. For the company behind each country and the money it settles in, see GET /v1/sbg/countries.

The drop-in button

If you do not want to call the API yourself, paste this instead. One script tag and one element, no build step and no framework.

<script src="https://sbg.example/embed/sbg-quote.js" defer></script>

<sbg-shipping-quote
  from-country="KE"
  from-area="Nairobi"
  length-cm="30" width-cm="20" height-cm="10" weight-kg="0.6"
></sbg-shipping-quote>

The button opens a destination picker, calls /shipping/quotes, and shows the price, where the buyer would collect it and when. Your page gets the whole quote:

document.querySelector('sbg-shipping-quote')
  .addEventListener('sbg:quote', (e) => {
    console.log(e.detail.price.amount, e.detail.price.currency);
  });

It renders in a shadow root. Your CSS cannot reach into it and its CSS cannot reach out. Crossing a border

A continental quote is a real one: it plans across the border, names the leg that crosses, and converts the far shop's price into the money you are billed in.

  • One currency, named. price.currency is the selling company's. Shops in another country are paid in their own money; the conversion happens in the quote.
  • The price has a shelf life. When a rate was applied, expiresAt is set. Re-quote after it, rather than honouring a stale figure.
  • The rate carries a buffer against the market moving between quote and settlement, and the buyer carries it. We do not profit from exchange rates: what the buffer absorbs is booked as an FX difference, not as margin.
  • A crossing needs paperwork. requires contains customs_declaration. When you mint the shipment you send its commercial invoice, or it is refused (CUSTOMS_INCOMPLETE) — see Its papers abroad below. Duties are the importer's — DDU — and none of it moves through us.
  • A border post costs time, and it is in the ETA rather than hidden in the driving.
Two currencies with no rate between them cannot be priced. You get FX_REQUIRED rather than a plausible wrong number. Adding one currency to another is not arithmetic, and a quote that pretends otherwise is worse than one that refuses.

Its papers abroad

A shipment that crosses a border goes with its commercial invoice: what customs reads, item by item. Send it as invoice on the mint; a test key checks it in full and keeps nothing. A shipment that stays inside a country needs none, and is told so if you send one.

"invoice": {
  "number": "INV-1043", "currency": "KES",
  "importer": { "name": "Abebe Kebede", "address": "Bole Road, House 12\nAddis Ababa" },
  "lines": [
    { "description": "Ankara shirt", "quantity": 2, "netKg": 0.6, "unitValue": 1700, "originCountry": "KE", "hsCode": "6205.20" }
  ],
  "declare": true
}
  • Each item: what it is, how many, its net weight, the value of one, and the country it was made in. An HS code only where you have one — your own, never suggested by us.
  • The buyer, by name, and the address you and the buyer settled on: it is carried exactly as you send it, line breaks and all, up to 300 characters — longer is refused, never cut. Leave the address out and the papers name the shop the buyer collects from.
  • The declaration: "declare": true is your signature. The invoice is fingerprinted, kept as signed, and never changed: a correction is a new one that replaces it, and the one replaced stays on the record.
  • Print three copies with the label and put them in the pouch on the outside of the parcel. The label says the papers are there, and the shop that takes the parcel in looks for them first: without them it does not take the parcel in.

GET/sbg/shipping/shipments/{id}/invoice  GET/sbg/shipping/shipments/{id}/invoice.html  PUT/sbg/shipping/shipments/{id}/invoice

Read it back, open the three copies to print, or correct it until the parcel is handed in — all with your secret key: the papers name your buyer.

message is an alias of detail for older clients. retryable says whether the same request may be sent again unchanged. traceId correlates the response with our logs — quote it if you report a problem. Some codes add a params object: a validation failure lists violations, a rate limit carries retryAfterSec.

Limits

  • 60 quotes a minute per caller, 30 shipments, and 120 for /areas. Generous for a product page, useless for a scrape. Exceeding it is a 429 with retryAfterSec.
  • Counted per KEY when you send one, and per IP when you do not — which is the practical reason to use one: without a key your limit is shared with everyone behind the same address.
  • A quote creates nothing and reserves nothing — asking it twice costs nothing and changes nothing, so it is always safe to retry. A shipment is the opposite, which is what Idempotency-Key is for.

Not here yet

Said plainly, because you will ask. None of these exist today and none of them are faked.

  • Amending a shipment. Cancelling is here now; amending is not, and will not be — see Reading and cancelling for why an edit that re-prices somebody's paid shipment is worse than making them create a new one.
  • Street-level addresses. The gazetteer places towns and neighbourhoods in Kenya and Ethiopia, not house numbers, and knows no other country. A production deployment swaps in a live geocoder behind the same interface.
  • More languages for the button. It ships English and Swahili, chosen by its locale attribute, and falls back to English for anything else rather than guessing. It is deliberately NOT wired to the network's own catalogues: those are thousands of English keys against a handful of stubs in other languages, and reading from them would dress a stub up as a translation on your checkout. Supply any language you need through window.SBG_QUOTE_STRINGS — your words always win, over ours and over the pack.
  • Minting from the button. It quotes. Turning a quote into a shipment is still the authenticated merchant API.
